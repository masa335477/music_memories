
## アプリ名： Music Memories

## 1. サービス概要
このアプリは、各々の好きな音楽への情熱を他人に共有するための音楽特化型SNSである。まだ自分の知らない楽曲に出会うことができるかも。

## 2. このアイデアはどこから生まれたか
音楽を聴くときに、自分が好きな楽曲を友達や恋人・職場の同僚にも紹介できるようにし、その楽曲の良さを分かち合いたいと思って作ろうとした。

### きっかけとなった体験・感情
音楽を聴いている中で、ただ自分が聴いて終わりではなく、その曲に対する思いを残すことができたらと思ったから。また、他人が自分の好きな曲に対して、コメントを残して分かち合うことができたならと思っている。

### なぜそれが「気になった」のか
- 自分の性格
自分はもともと音楽を聴くことが大好きである。毎日家でもスマホで音楽を聴くし、通勤する時も車でCDをかけるのが当たり前である。
- 過去の経験
自分の好きな楽曲を他人にもっと聴いてもらえるきっかけを作ることができたならと思った。
音楽鑑賞アプリ（SpotifyやApple Music等）では、楽曲を聴くことに特化しているため、コメントを残すことはどうしても重視していない印象があった。
そこで、一つのアプリで音楽を聴く（音楽アプリと連携）ことも、コメントやいいねもできるコミュニティを作りたいと考えた。

## 3. 課題の整理

### 表に見えている困りごと
既存SNSでは、音楽以外の話題も表示されること。

### 本当に解決したい課題
他の話題に振り回されない、音楽に特化したサービスを作りたい。
→これは、高い熱量を持った音楽の感想を探す時に、それが雑多な話題に埋もれてしまうことで、結果的に時間がかかってしまうからである。

他人の好みを重宝しつつ、自分の好みも大切にしたい。
→どんなに各々の好きな楽曲を語っても、反応や共感を得ることは難しい。音楽の好みや聴き方は人それぞれであり、日常の話題が中心となる既存のSNSでは、お互いの趣味がぴったり重なるタイミングを見つけるのは少し難しいであろう。いきなり知らないアーティストの楽曲を勧められた際、どうしても「この曲自分に合うかわからない」という不安は誰にでもある自然なことである。

## 4. 想定ユーザーについて

### どんなユーザーを想定しているか
- アルバム単位でじっくり楽曲を聴くユーザー
アルバムを通して聴くことは、楽曲の構成や楽曲と楽曲同士とのつながりから得るドラマ性を味わうことができるといったメリットがある。また、同じ楽曲でも、その楽曲が収録されているアルバムを通して聴くことにより、単体で聴く時とは違う印象を持つと考える。本アプリは、そんな楽曲単体で聴く人より、アルバム全体で聴いたときの感情を共有したいという人にお勧めしている。

- もっと好みを深めたい・広げたいユーザー

### 実際に使われる可能性について(需要・存在意義)
- 需要
近年XをはじめとするSNSを通じて好きな音楽やコンサートについてテキストで熱弁するユーザーが増加している。しかし、既存の総合SNS（特にX）は日常の雑多な話題も多く表示ため、「音楽の話題だけを見たい・盛り上がりたい」「熱量の高いレポだけを読みたい」という音楽ファンの需要を完全に満たしているとは言えない。また、音楽の投稿が他の話題に埋もれてしまう点もある。

- 存在意義
本サービスは、「音楽関連の思い出」のみ投稿可能となっている。
雑多な話題をタイムラインから排除するため、ユーザーは本当に興味のある音楽の話題だけに集中でき、熱量のあるコメントを通じて、真の音楽体験を通して新しい音楽と出会える。

### ユーザーがサービスを導入して利用するまでのイメージ(導入・継続の流れ)
ある音楽を聴くことが大好きなユーザーがいるとする。そのユーザーはある歌手の楽曲をよく聴いている。しかし、ある時楽曲の魅力やライブの感想を探すのに時間がかかっている。するとユーザーは音楽の投稿だけを読めるようなアプリがあったらと考える。そこで、そのユーザーが本アプリを導入（インストール）する。そして楽曲の魅力について説明文を書く。すると、他のユーザーから何件もの共感コメントがもらえた。すると、これなら音楽好きなユーザーと音楽のことだけで話し合えると思い、使い続けたいと考えた。

### それでも自分が作りたい理由
上記の機能に加え、以下の機能を加えたいと考えている。
①アルバムの投稿機能（Melologとの比較）
本サービスでは「アルバム単位での投稿」も軸に据える。これは、楽曲単体では語り尽くせない「楽曲構成」「曲順の妙」「曲と曲の繋ぎ」「作品全体のストーリーや空気感、メッセージ性」まで語り合うことができる場にしたいと考えている。また、「1曲がアルバムの中でどういった役割を果たしているか」を語ることの楽しさも味わえる。

②ランキング形式での投稿（全アプリとの比較）
一つの投稿（スレッド）に対して、複数の楽曲やアルバムをランキング形式でストック・共有できる機能を実装する。
例えば、「人生を変えた楽曲3選」や「初めて聴いた時に衝撃を受けた曲ベスト5」といった、ユーザー独自のテーマに沿ったセレクトを可能にする。また、単発の曲紹介ではなく、順位やテーマという「文脈（コンテキスト）」を持たせることで、投稿者は選曲のこだわりをより深く表現できる。これにより、見る側にとっても「タイパ良く、直感的に新しい音楽と出会える」というメリットが生まる。

この①と②の機能を使うことにより、新しい楽曲に出会うことが容易になると考える。

③グラデーション・レコメンド機能の実装（全アプリとの比較）
本アプリでは、「自分の大好きな楽曲・アルバム」を大切に語れる場所をベースにしつつ、相手のこれまでの好みにそっと寄り添う『グラデーション・レコメンド』などの仕組みを取り入れる。 聴き手の心の準備やペースに配慮した動線を作ることで、無理なく自然に「それなら、ちょっと聴いてみようかな」と思える、心地よい共感の輪を広げていける場所を実現する。

例えば、
1. ユーザーが好きなアーティストに「サカナクション」を登録
2. 「サカナクションが好きな人がよく聴くバンド」
3. 「同じく日本語詞とメロディを重視するバンド」
4. 「少し方向性の違うバンド」
5. 「あなたの好みから少し離れているが、共通点のあるアーティスト」

というように、既知 → 近い → 少し違う → 未知という段階を作る。

### Musicboardとの差別化について
本アプリは、楽曲やアルバムについて投稿・評価・記録することができるという点で、Musicboardと共通している。そこで、本アプリでは単に音楽を評価・記録するのではなく、「その楽曲・アルバムを好きになったきっかけ」「自分にとってどのような楽曲なのか」等といったユーザー自身の音楽体験を共有することを重視する。
また、アルバム全体について語れる投稿や、テーマに沿って複数の楽曲・アルバムを選出するランキング投稿などを実装する。これにより、単一作品の評価だけでは表現しきれない、ユーザー自身の音楽観や思い出を共有できるようにする。


### 差別化を「体験価値」で表現すると
①1曲単位では語りきることのできない、アルバムならではのストーリー性を含めた熱量を語れる場所。
②人の好きという感情を通じて音楽を知り、語り、さらに新しい音楽へ出会おう。

## 8. このアプリの懸念点とその対策

### 懸念点
ChooningやMusicboard、Record Clubなどの先行類似サービスが存在するため、機能やコンセプトが重複し、新規ユーザーに見向いてもらえない、または既存サービスから移行してもらえない懸念がある。

### 対策
- 3つの「機能・体験的アプローチ」によるポジショニングの明確化
既存サービスには、楽曲の記録やアルバムの評価を中心としたサービスが存在する。一方、本サービスでは、「評価すること」よりも、「なぜその音楽が好きなのかを語ること」「好みを他者と共有すること」に重点を置く。

1. 投稿単位の差別化（アルバム・ランキング特化）：
1曲単位ではなく、「アルバムの曲順や流れ」や「テーマ別ランキング（ベスト3など）」に特化。単なる記録ではなく、音楽ファンの「1曲では語りきれない熱量」を解放する場にする。

2. 心理的ハードルを下げる「グラデーション・レコメンド」：
他社のようにAIが突飛なおすすめを出すのではなく、「自分の投稿 ➔ 相手の好みの提示 ➔ いいね ➔ 次のおすすめの段階的開示」という、ユーザーの警戒心（知らない・苦手な曲への抵抗）を汲み取った優しいレコメンド動線を独自実装する。

3. 優しさに配慮したUI/UX（未知の音楽を押し付けられないUX）：
試聴時に10秒かけてゆっくりフェードインする機能や、ジャケット写真をあえて小さくする配慮など、「押し付けない、傷つかない安心感」を徹底することで、既存の激しいSNSや批評サイトに疲れたユーザーの受け皿となるだろう。
